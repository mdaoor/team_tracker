# ADR-0006: Review-queue ownership tie rule
Date: 2026-10-23   Status: accepted

## Context
UX §3.2: the same item must never appear in two managers' queues.

## Decision
`review_owner(item)` returns exactly one person: the assignee's primary `line` manager if that person also manages the item's
project (owner, or `ProjectMember` owner/manager); otherwise the project owner. Private Inbox projects have no managers, so the
primary line manager owns their rows, falling back to the workspace's first member. A row is shown only to its owner.
Rows are `ReviewItem`s (status `open`) and unconfirmed `Classification`s on work items.

## Consequences
A property test over random reporting graphs checks that every row appears in exactly one queue and none is orphaned.
Missing-estimate and policy-style rows are not generated by capture; Phase 8 policies own those.
