# Phase 9 — Governance UI: policies, violations inbox, habit report, insights review, weights

## Goal
Managers author policies from templates (Tier 1) or CEL (Tier 2) with type‑checking and dry‑run, triage violations, review habits for 1:1s/retros, review AI insights, and manage weight schemes — all in the web app, respecting ACL.

## Depends on
Phase 8 (engine + APIs), Phase 5 (shell), Phase 6 (views; violations/habits layouts plug into the Views area).

## Inputs
- Object model §8 (Policy authoring tiers), §9 derived views (Violations inbox, Habit report, Team performance, Manager digest), §10 permissions
- UX §3.1 (Policies, Weights nav), §4.2 (layouts), §6

## Scope
1. **Policies**: list (active/inactive, category, severity, last fired, open violations), template gallery with parameter forms, CEL editor (CodeMirror 6 with CEL grammar highlighting, autocomplete from the context schema doc endpoint, inline type errors), candidate filter builder (reuses the P6 filter chips), dry‑run panel (`PolicyTestRun` results with sample targets → drawer), activation gate, notify/auto‑action editors, scope picker, version history (from events).
2. **Violations inbox**: grouped by severity/policy/category, filter chips (grammar keys), row actions acknowledge/resolve/waive(reason)/false‑positive, bulk, link to item drawer (which shows its violations tab), "mine" (as accountable person) vs "my team".
3. **Habit report**: per person/team, positive vs negative, rate, trend arrows, sparkline over windows, linked violations drill, status (`observed → flagged → in_coaching → resolved`), coaching note (manager‑only, `habit.coach`), export for 1:1 (stamped). Wellbeing section collapsed with "restricted" when not permitted (UX §6).
4. **Team performance** view: `MetricSnapshot` time series per team/person/product/project (throughput weighted, hours, cycle time p50 per stage, overrun rate, estimate accuracy, violation counts, risk exposure), weight scheme selector, compare periods; charts follow the prototype's token palette.
5. **Manager digest**: for a scope and window: daily logs (confirmed/unreviewed), notable events, pinned context notes, new insights; "mark reviewed" for daily logs.
6. **Insights review**: list of `Insight`s with status actions; regenerate button; supporting evidence links.
7. **Weights**: `WeightScheme` editor (formula builder with the P3 grammar, live preview on a sample of items), per‑item override panel, "which scheme does this view use" indicator.
8. **Notifications** centre (in‑app) fed by P8 `notifications`.

## Out of scope
Slack delivery of notifications (P11); new engine features.

## Detailed tasks
- Context schema endpoint for the editor: `GET /governance/context-schema?version=1` (fields, types, functions, docstrings, examples) generated by P8.
- "Describe the rule" box: natural language → LLM gateway `/v1/policy/author` (Phase 2b; the agent validates with `policies:check` and dry‑runs) → pre‑filled template form or CEL draft, always shown as a draft the manager reviews.
- CEL editor: debounce 400 ms → `POST /policies:check {cel, target, version}` → errors with positions; snippet library from templates ("insert template as CEL" for power users).
- Template form: generate controls from `params` (`int → number input with min/max`, `stage → select from process`, `dimension → select`, `duration → unit+value`); show the compiled CEL read‑only below ("What this does" in plain words from `description` with params substituted).
- Dry‑run panel: run → progress → fired count by severity, histogram over time, sample list (max 50) → click → item drawer; "Activate" enabled only when a run exists after the last edit; admins see "Activate anyway".
- Violations inbox: default grouping severity → policy; row shows pill (severity colours from prototype), target key, policy name, detail (`Violation.evidence` rendered as "field: value" chips), accountable person, age; keyboard `a/r/w/f`; waive requires a reason (modal) and shows waiver on hover afterwards.
- Habit report: table per subject with positive first (prototype order), `↑ → ↓` trend glyphs (prototype), click → drawer with window comparison, linked violations list, status control, coaching note editor (autosave; visible to manager roles with `habit.coach` and to the subject? **No** — coaching notes are manager‑only; the subject sees status only. ADR‑0014).
- Team performance charts: line/bar with `--s1..s8` palette, table toggle, CSV export (stamped), period compare (shaded previous window).
- Weights editor: multipliers table (dimension/value typeahead → factor), base selector, clamp; preview panel recomputes 20 sample items via `POST /weight-schemes:preview`.
- Notifications: bell with count from `/notifications/mine?unread=1`, list, mark read, deep links.
- Tests: Vitest for template → form generation and CEL error mapping; Playwright: create a `stuck_in_stage` policy from template with 3 days on `test`, dry‑run shows the four WEB items, activate, violations inbox lists them; waive one with a reason; habit report hides wellbeing for a project manager.

## Acceptance criteria
- [ ] A non‑technical manager can create, test and activate a template policy without seeing CEL (usability check script in `docs/ux/checklists.md`).
- [ ] A `policy_admin` sees inline type errors with the field name within 1 s of typing.
- [ ] Violations inbox actions update the engine state (verified via API) and the item drawer tab.
- [ ] Habit report respects §10/§13.3 rules; coaching notes never render for the subject.
- [ ] Weight scheme preview equals server recomputation for the sample.
- [ ] All charts have table toggles and pass the accessibility audit (≥ 95).
- [ ] Manager digest for `platform` team over 14 d renders daily logs, events, pinned notes, insights.

## Exit checklist
- [ ] `docs/web/governance.md` (screens, permissions, keyboard map).
- [ ] ADR‑0014 coaching note visibility.
- [ ] Storybook stories for policy form, CEL editor states, violation row kinds, habit row.
